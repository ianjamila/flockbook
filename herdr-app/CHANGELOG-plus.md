# Flockbook plus: changes against upstream

Base: upstream `main` at `0cadf31` (after v0.13.0). What each change is for, in plain words, is in the
[README](README.md#flockbook-plus-this-build); this file says where it lives.

## Helper (`xplat/`, Rust)

| Commit | Change |
|---|---|
| Helper: send over Claude Code's suggested command (+ red test) | Replaced by upstream's own fix when upstream fe57f10 was merged in (11-13): the helper reads the box's first paint and sends over a dim suggestion (`queue.rs` `claude_suggestion_in_paint`). A "/word" really typed still gets the chat's Send anyway. The helper is now upstream's, unchanged. |
| Question answers: a comma in a single-choice label is not ambiguous (+ red test) | `herdr-core/src/question/claude_exact.rs`: only a multi-select answer splits on commas. Upstream merged it (PR #12). |

| Parked Claude tabs (11-13) | Claude Code can move a terminal's conversation to its background service ("parked": the client's pid file gets `parkedJobId`; the session runs on as a `bg` process whose pid file has that `jobId`). `herdr-core/src/resolver.rs` `claude_parked` follows it (in the terminal's process tree, else anywhere), and the session lookup now names the job's session (a parked client's own old one, or a `bg` job a client merely started, no longer makes it ambiguous). `flockbook-modfeed/src/parked.rs` gives such an agent the job's status (blocked while a prompt or question picker is on screen, else working/idle from the pid file) in every command, the phone page and queue, and the new `parked` command lists them (docs/protocol.md). |
| Send anyway on any machine (11-14) | `send --over-suggestion </word>` (`cards.rs` `clear_suggestion`, `queue.rs` `claude_lone_slash` / `claude_box_one_row`): after the agent and conversation checks, the helper where the terminal runs clears Claude Code's lone "/word" line (Ctrl-E Ctrl-U) and sends only into a box down to one row. The mod's Send anyway calls it for every tab, so a tab on another machine gets it too (it was offered only for this computer's tabs). `queue.rs` `box_edges`: a named session's titled top edge ("──── name ─") is the box's top, so its text is checked (the box was not found before). |
| A new Claude tab’s session (11-14) | `herdr-core/src/resolver.rs` `claude_bare_session`: the bare session id a Claude pane’s pid file names (written at start and on `/clear`, before the conversation has a log) and the config folder that holds it. `flockbook-modfeed/src/locate.rs` `Entry` keeps them (`sid`, `config`; left out when empty, so older readers are unaffected) while no log is found, so the mod’s Resume knows which session a brand-new tab holds. |
| Send anyway checks the helper on the other machine first (11-14) | `protocol.rs` `ABILITIES` (`send-over-suggestion`, `bare-session`) in every header and at the end of `version`'s commands. Every build says 0.1.0, so an older helper there passed the version check and took `--over-suggestion` for text. `remote.rs` `lacks`: before a Send anyway there, the helper there is asked for `version` (nothing else runs); without the ability it answers `remote_helper_outdated` with `remote.missing`, nothing is sent, and the install card offers this build's helper over the reply box (`composer.js` `helperAsk`, `chat.js` `sendHelperCard`, `helpercard.js` `sendCard`: "older than this Flockbook"; an older helper still reads, so no failed feed draws it), with Send anyway kept to press again. Other commands still run on an older helper; only an option before `--text` counts. Red tests: `tests/remote.rs`, `tests/cli.rs`, `test/remote.test.mjs`, `test/plus/test-sendanyway.mjs`. |
| Answer on a parked or named tab (11-13) | A named Claude Code session (parked, or renamed) draws its name in a rule under the question picker, below its key line. `herdr-core/src/question/claude_exact.rs` `above_name_rule` drops that one rule before the exact picker and review compares, which took the last line as the key line and refused every answer from the chat ("The question on screen changed before the answer went in"). |
| The same in the Mac app (11-13) | `Sources/HerdrKit/QuestionAdapter+ClaudeExact.swift` `aboveNameRule`: the twin of `above_name_rule` for the Mac app's `claudeExact` and `claudeReviewExact` (they had the same last-line check). Check `ChecksClaudeNameRule.swift` (twin of the Rust test). |

Upstream PR #12 (long questions, the "edit in <editor>" key line, typed capitals on the hc backend) is
already in upstream `main`.

## Mod (`mods/flockbook/`)

New files:

| File | What it does |
|---|---|
| `where.js` | Which machine a tab is on (`wsl/t3`), a machine's home (asked once), the helper's cache entry there, and the `claude_machine` setting: the About lines, Summarize and Resume run `claude` on that machine (Windows can't run it itself); projects with a `machine` move only that machine's tabs, between its own workspaces (s26). |
| `accounts.js` | The Claude Code accounts tabs run as (`accounts` setting): which one a screen shows, its name, its config folder, the `claude` command for it (finds `claude` in the usual folders, or `claude_path`). |
| `ai.js` | About lines and the Haiku calls behind them and Summarize: one call gate (known account, not paused, under the daily cap), usage-limit pauses with the reset time read in any time zone, per-account counts. One day rule for every time shown (`dayWord`/`clockText`): "tomorrow 1:00 am", "yesterday 9:10 pm", a weekday within 6 days, else the date; `history.js whenText` uses it too. |
| `asks.js` | Reads each agent's screen every 15 s (this Mac's and other machines', e.g. `pc-wsl/t3`): replies that end asking you something, review-pipeline asks (setting), hand-offs (setting), background shells/agents, CI and review waits, MCP input requests, the "Now:" line, merged-PR checks via `gh` (setting). |
| `automove.js` | Move to <workspace> (tab menu), automatic moves to project workspaces and the wrong-workspace badge, from the `projects` setting. |
| `history.js` | "Since you last looked": per-tab snapshots and events (finished, needs you, waiting on CI, waiting on a review, hand-off, About, PR merged/closed), Copy and Mark seen, "waiting 2 h". 11-13: grouped by what each tab does now (`SINCE_GROUPS`), a card per tab (`nowText`, About line, change chips), times name their day (`whenText`); `overview.js` draws it, click opens the tab, every group folded at first + Expand all / Collapse all, Copy = the grouped text with a notice. |
| `hover.js` | The hover box on cards, tab pills and tab-list rows. |
| `patchcheck.js` | Warns once when an official update replaced the patched helper (only after a patched one was seen here). |
| `machines.js` | Other machines in the sidebar, as Herdr's own sidebar groups them: a header per machine once one besides this computer is known (`hc machine ls` every 15 s, `machines()`, the spaces' `machine`), with fold, + for a new workspace there, a New workspace there / Loading… row, its state, the login command with Copy, Connect for a rebuilt machine; `spaceTitle` ("api on pc-wsl"). |
| `parked.js` | Parked Claude tabs (their conversation went on in Claude Code's background service, so Herdr lists no agent there): a 3 s tick asks the helper's `parked` command while a Claude terminal reports no status, and `agents()` / `spaces()` (which every module now imports from here, not from "herdr") add them back with their job's status, "done" until you look, as Herdr does. |
| `sessions.js` | The Resume sessions dialog (`sessions` view; sidebar row, Overview link, ⌘⇧R = `flockbook.sessions`, `state.js showSessions`): the closed Claude conversations of every account on this computer and the `claude_machine`, found by ONE fixed `sh` script per machine (`LIST_SCRIPT`: find/stat/grep, days, cap and config folders as positional arguments, run through `where.js execAt`), with search, tick boxes, Select all shown / Clear and a batch Resume that places each session by project workspace, else "~", else a new workspace on its machine (`resume.js liveSids` keeps running sessions out). 11-14 s28: a folder is opened exactly as the log names it (a cut-off one is unknown); a Claude tab not identified yet blocks every resume on its machine until it is; a resume claims its session before any wait; the dialog and the restart offer share "being opened" claims (`resume.js` `openingNow` / `noteOpened`); a session of this computer with no project or "~" workspace opens in the shown workspace only when it is this computer's, else in a new "~" here. Fable: a session changed in the last 5 minutes is marked (it may run in a terminal outside Herdr) and left out of Select all; sessions in sub-agent tabs count as open. |
| `state.js`, `asks.js` (s29) | Owner 11-14 "Live work wins": `subStatus` puts a working tab (or one with a live wait or background agent) under its live work; ✅ there is a hint word, not "results waiting" or "waiting on you"; `nowWait` reads a working tab's Now line ("Waiting for the round 10 Codex job" → Waiting on a review; CI → Waiting on CI); REVIEW_WAIT knows "round N / RN Codex". |
| `resume.js` | Remembers each Claude tab's session and offers them back after a restart (Resume, Resume all, Dismiss, "Opening…"). 11-14: on another machine whose workspace is gone, a session opens in that machine's "~" workspace, else a new one named "~" that the rest of a Resume all (and a Resume sessions batch, `sessions.js`) wait for and share, instead of one workspace each. s28: the same local placement for the offer's Resume; downtime noted while a tab was unidentified is kept across such polls. Fable: Resume waits only for an unidentified tab on the session's own machine; the status call for an unidentified remote tab goes once a minute at most. s29 (Fable P3): restart offers are judged per machine too: an unidentified tab holds back only its own machine's sessions, which keep their downtime (`gaps`) and away time for a later poll. Known limit (owner 11-14: follow-up only): Claude tabs running natively on Windows are not resumed. 11-14 (s31): a Claude tab is identified before its first message (the helper’s cache carries the session id Claude Code’s pid file names, `sid` + `config`; `sessionOfEntry`); a tab still unidentified holds back only the sessions its live command line may hold (`couldBe`/`mayBe`: plain `claude` none, `--resume <id>` that one, `--continue` its folder’s, anything else all), with no timer; Resume all returns to the workspace and tab you were on (`placeNow`/`backTo`/`returnTo`; idea from [herdr-sessions](https://github.com/maboch/herdr-sessions), Apache-2.0, no code copied). |
| `selection.js` | Text selection in the kit's text boxes in the theme's selection colour. |
| `statusline.js` | Each session's own status line in the chat header (with `extras/flockbook-statusline`). |
| `summary.js` | The "Summarize this tab" dialog. |
| `tabs.js` | The vertical tab list. A working agent's icon dances (two native `loop`s: hop + sway; `dances`, setting `dance`, on by default). |
| `termresize.js` | Drag-resize grips for the terminal window, and its size presets. `fitTerm`/`termAt`: the window stays clear of the tab list (it only shrinks, to the work column right of its remembered spot; a window never dropped is centered in the work column). |
| `icons/moved.svg`, `icons/tablist.svg`, `icons/monitor.svg`, `icons/server.svg`, `icons/chevron-down.svg`, `icons/chevron-right.svg` | Their icons. |
